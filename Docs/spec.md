# Спецификация (SDD): Семантический FAQ-бот с админкой на Next.js

## 1. Описание проекта
Telegram-бот, который отвечает на вопросы студентов, используя базу знаний (FAQ). 
Бот НЕ генерирует ответы "из головы". Он использует векторную БД для предварительного поиска, а затем применяет легковесную LLM в роли "Судьи" для выбора единственно верного статичного ответа. 
Интерфейс преподавателя реализован в виде веб-приложения на Next.js. Весь проект реализован в едином стеке на TypeScript/Node.js.

## 2. Стек технологий (Fullstack TypeScript)
- **Telegram Бот:** Node.js, библиотека `grammY`.
- **Фронтенд и Бэкенд админки:** `Next.js` (App Router, React, TailwindCSS).
- **База данных:** `SQLite` + `Drizzle ORM` (логи и база FAQ-элементов).
- **Векторная БД:** Qdrant, запущенный локально через Docker Desktop (`docker-compose.yml`). Данные хранятся в папке `qdrant_storage/` (volume mount).
- **Эмбеддинги и LLM:** API Mistral (`mistral-embed` для векторизации, `mistral-small-latest` для извлечения Q&A из неструктурированных документов и выбора ответа ботом).
- **Парсинг документов:** `pdf-parse` (PDF), `mammoth` (DOCX), `exceljs` (Excel .xlsx).
- **Окружение:** `dotenv` для ключей.

## 3. Архитектура и логика

### 3.1 Пайплайн загрузки базы знаний (два пути)

Преподаватель загружает материалы через веб-интерфейс. Путь обработки зависит от типа файла:

**Путь A — Excel (.xlsx):** Самый быстрый способ. Файл содержит готовые пары Q&A в колонках.
1. Преподаватель загружает `.xlsx` файл (колонки: `question`, `answer`).
2. Сервер читает строки напрямую через `exceljs` — LLM не нужна.
3. Пары сохраняются в `faq_items` со статусом `pending`.

**Путь B — PDF / DOCX:** Для загрузки неструктурированных учебных материалов.
1. Преподаватель загружает `.pdf` или `.docx` файл.
2. Сервер извлекает текст (`pdf-parse` / `mammoth`).
3. Текст отправляется в `mistral-small-latest`: *"Извлеки все пары вопрос-ответ, верни JSON `{pairs:[{question,answer}]}`"*.
4. Пары сохраняются в `faq_items` со статусом `pending`.

После загрузки (любым путём):
5. **Ревью:** Преподаватель видит все `pending`-пары в таблице с кнопками на каждой строке.
6. **Публикация:** По кнопке «ОК» статус → `active`, элемент векторизуется через `mistral-embed` и загружается в Qdrant (payload: `id`, `question`, `answer`).

### 3.2 Обработка сообщения (Бот) — Гибридный поиск
1. Пользователь пишет вопрос. Текст векторизуется через `mistral-embed`.
2. Выполняется поиск по Qdrant — извлекаются **Топ-3** самых похожих вопроса-ответа.
3. Топ-3 и вопрос пользователя отправляются в `mistral-small-latest`: *"Выбери FAQ, который точно отвечает на вопрос. Верни только ID. Если не подходит ни один — верни 'NULL'"*.
4. Если LLM вернула ID: бот выдаёт заготовленный ответ из FAQ.
5. Если LLM вернула `NULL`: бот отвечает "Не нашёл ответа" и выдаёт Inline-кнопку "Связаться с преподавателем".

### 3.3 Логирование
Вопросы, получившие `NULL`, записываются в `unanswered_queries` (поля: `id`, `user_id`, `question_text`, `timestamp`).

## 4. Схема базы данных (SQLite / Drizzle ORM)

### Таблица `faq_items`
| Поле | Тип | Описание |
|---|---|---|
| `id` | integer PK | Автоинкремент |
| `question` | text | Вопрос |
| `answer` | text | Ответ |
| `source_document` | text | Имя исходного файла |
| `status` | text | `pending` / `active` / `deleted` |
| `created_at` | integer | Timestamp создания |

### Таблица `unanswered_queries`
| Поле | Тип | Описание |
|---|---|---|
| `id` | integer PK | Автоинкремент |
| `user_id` | text | ID пользователя Telegram |
| `question_text` | text | Текст вопроса |
| `timestamp` | integer | Timestamp |

## 5. Веб-интерфейс администратора (подробно)

### Страница «База знаний» (`/admin/faq`)
**Панель действий (вверху):**
- Кнопка «Загрузить Excel» — открывает file picker, принимает `.xlsx`. Пары читаются из колонок `question` / `answer`, сохраняются как `pending`.
- Кнопка «Загрузить документ» — принимает `.pdf` / `.docx`. Запускает LLM-экстракцию Q&A.
- Кнопка «Выгрузить в Excel» — скачивает все `active` FAQ-пары в `.xlsx` файл.
- Фильтр периода — два поля «с» / «по» (date picker), фильтрует таблицу по `created_at`.

**Таблица FAQ-пар:**
- Колонки: `#`, `Вопрос`, `Ответ`, `Источник`, `Статус`, `Дата`, `Действия`.
- На каждой строке три кнопки:
  - **ОК** — статус → `active`, публикация в Qdrant (для `pending`-строк).
  - **Отмена** — статус → `deleted`, удаление из Qdrant (если был `active`).
  - **Редактировать** — открывает inline-форму (или модальное окно) для правки `question` и `answer`. После сохранения, если статус был `active`, обновляет вектор в Qdrant.

### Страница «Неотвеченные вопросы» (`/admin/unanswered`)
- Фильтр периода («с» / «по»).
- Таблица: `#`, `Пользователь`, `Вопрос`, `Дата`.
- Кнопка «Выгрузить в Excel» — скачивает отфильтрованные записи.

## 6. Структура репозитория (Единый проект Next.js)
- `/src/bot` — логика Telegram-бота (обработчики сообщений).
- `/src/app` — страницы и API-роуты админки Next.js.
- `/src/db` — схемы Drizzle ORM, миграции, подключение к SQLite.
- `/src/lib/qdrant` — настройка клиента Qdrant.
- `/src/lib/parser` — парсинг PDF/DOCX/Excel и извлечение Q&A.
- `logs.db` — файл базы данных SQLite (в корне).
- `.env` — ключи (TG_BOT_TOKEN, MISTRAL_API_KEY).

## 7. Требования к безопасности
- Строго использовать `.env` для всех секретов.
- Ограничить размер загружаемого файла на сервере (не более 10 МБ).
- Разрешать только типы: `application/pdf`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
- Файлы `.env`, `logs.db`, `qdrant_storage/`, `node_modules/`, `.next/` в `.gitignore`.
