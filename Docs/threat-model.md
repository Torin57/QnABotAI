# Threat model (лёгкий чек-лист)

Масштаб: пилот — один преподаватель (владелец = единственный админ), анонимные студенты через Telegram, один сервер (dev и prod совмещены). Это **не** полноценный threat-model документ; пересмотреть при переходе к P2 (multi-tenant / SaaS).

Последняя ревизия: 2026-07-05 (trust boundaries).

## Что защищаем (активы)

- База знаний и журнал (`logs.db`) — единственный источник правды.
- Секреты: `TG_BOT_TOKEN`, `MISTRAL_API_KEY`, `SESSION_SECRET`, пароль админки.
- Доступ к админке (изменение базы знаний = изменение ответов бота студентам).
- Деньги: API Mistral оплачивается за использование.
- Анонимность студентов (инвариант №1 в `spec.md`).

## Trust boundaries (границы доверия)

Кто кому доверяет и где стоит контроль. Масштаб пилота: **один tenant** (одна база знаний, один бот, одна админка).

```
[Студенты Telegram]          untrusted
        │
        ▼  rate limit 3/мин, без userId в БД
   [Telegram-бот]
        │
        ▼  «Судья» возвращает только ID или NULL; ответ — только из qna_items
 [Qdrant + Mistral API]

[Админ (cookie-сессия)]      trusted (единый пароль)
        │
        ▼  proxy.ts: cookie на /admin/*, /api/qna/*, /api/log/*
   [Next.js API]
        │
        ▼
 [logs.db + Qdrant]

[Upload PDF/DOCX/XLSX]       untrusted
        │
        ▼  allowlist MIME, magic bytes, лимит 10 МБ; буфер в памяти, на диск не пишется
   [парсер → qna_items]

[Секреты .env.*.local]       trusted zone, вне git и .cursorignore
```

| Граница | Доверие | Контроль |
|---|---|---|
| Telegram → бот | Нет | Rate limit, без сохранения `userId` |
| Бот → LLM | Частичное | «Судья» не генерирует текст; prompt injection → максимум нерелевантный ответ из базы |
| Интернет → админка | Нет | Пароль + signed cookie + rate limit логина |
| Upload → сервер | Нет | Magic bytes, MIME allowlist, лимиты размера/строк |
| Dev ↔ prod | Разделены | Отдельные `.env.{env}.local`, отдельные bot-тokens (`decisions.md` 2026-07-04) |

### Tenant boundaries

**Не применимо на пилоте:** один преподаватель, одна `qna_items`, одна коллекция Qdrant, один `TG_BOT_TOKEN`. Разделение данных между преподавателями (`tenant_id`, отдельные боты/коллекции) — задача P2 «Мультипреподавательский режим»; пересмотр trust/tenant boundaries — по триггерам в конце документа.

## Чек-лист угроз и митигаций

### Закрыто (реализовано, см. `spec.md` §5.0, §7)

- [x] **Подбор пароля админки** → bcrypt-хеш + rate limit логина (5 неудач с IP → 429 на 15 минут).
- [x] **Кража/подделка сессии админки** → подписанный HMAC-SHA256 `httpOnly` cookie, `SESSION_SECRET` вне git.
- [x] **Доступ к API админки в обход UI** → middleware проверяет cookie на `/api/qna/*`, `/api/log/*` → 401.
- [x] **Утечка секретов через git** → все `.env.*.local` в `.gitignore`, в истории git секретов нет (проверено 2026-07-05), права 600.
- [x] **Спам бота / сжигание бюджета Mistral** → rate limit 3 вопроса/мин на чат, запрос не доходит до Qdrant/Mistral.
- [x] **Вредоносный файл при импорте** → allowlist MIME-типов, лимит 10 МБ, magic bytes, лимиты пар/длины.
- [x] **Prompt injection в вопросе студента** → бот не генерирует текст: «Судья» возвращает только ID кандидата или NULL, ответ всегда статичен из базы. Худший исход — нерелевантный, но легитимный ответ из базы знаний.
- [x] **Потеря данных** → ежедневный бэкап `logs.db` (cron, ротация 7), restore-тест пройден; Qdrant восстанавливается reindex-ом.
- [x] **Деанонимизация студентов через нашу БД** → `userId` не пишется нигде (инвариант); rate-limit-счётчики только в памяти.
- [x] **Использование prod-бота из dev** → отдельные боты и токены на окружение.

### Принятые риски (осознанно, под масштаб пилота)

- [ ] **Компрометация сервера = компрометация всего** (dev и prod на одной машине, секреты и бэкапы на том же диске). Принято решением пользователя; off-site копия бэкапов — в backlog P1.5.
- [ ] **Cookie сессии живёт 1 год, отзыва нет** (нет server-side session store). Утечка cookie = доступ до смены `SESSION_SECRET`. Ротация `SESSION_SECRET` — ручная мера реагирования.
- [ ] **In-memory rate limit сбрасывается при рестарте** и не работает на несколько инстансов. Для одного процесса — достаточно.
- [ ] **8 moderate npm-уязвимостей** в транзитивных dev/build-зависимостях (esbuild, postcss, uuid) — разобраны и приняты 2026-07-05, см. `plan.md`/`decisions.md`.
- [ ] **DoS на уровень выше приложения** (флуд HTTP, Telegram-флуд с многих чатов) — не митигируем на пилоте; при проблемах — reverse-proxy с лимитами.

### Реагирование на инциденты (шпаргалка)

- Утёк `TG_BOT_TOKEN` → revoke через @BotFather, обновить `.env.*.local`, перезапуск.
- Утёк `MISTRAL_API_KEY` → перевыпустить ключ в консоли Mistral, обновить `.env.*.local`.
- Подозрение на доступ к админке → сменить пароль (`npm run admin:hash-password`) **и** `SESSION_SECRET` (инвалидирует все cookie), перезапуск.
- Порча/потеря данных → восстановление по `spec.md` §7.3.

## Когда пересматривать

- Появление второго админа / преподавателя (login + роли).
- Выход за пределы одного сервера (staging/prod разнесены, несколько инстансов).
- Публичный SaaS-режим (P2) — потребуется полноценный threat model.
